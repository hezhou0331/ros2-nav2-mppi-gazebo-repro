# 建图前输入故障检查

2026-09-13 更新：[静止复检](STATIONARY_CHECK.md)的三分钟输入窗口通过，源端到接收的缺口仍有记录；完整预检因真实外参缺失退出 2，硬件同步未验收。以下历史结果按各自窗口解释。

此前一轮完成三项工作：定位接收缺口、补齐运行保护、扩大真实录包故障回放。保护测试通过，真实三分钟稳定性检查没有通过：后雷达出现约 0.300004 秒的点云时间间隔，超过当前 0.25 秒阈值，适配输出锁定。完整真机部署准备仍未通过。

## 1. 缺口定位结果

180 秒内同时观察 Zenoh 源消息和独立 ROS 接收。四路源 GID 均保持稳定；发现的异常全部属于发布序号缺口，没有发现“序号连续但设备时间断档”的事件。

| 数据 | 序号缺口事件 | 探针缺少的序号数 | 相应区间中另一 ROS 链收到的样本数 |
| --- | ---: | ---: | ---: |
| 前点云 | 35 | 37 | 6 |
| 前 IMU | 51 | 158 | 102 |
| 后点云 | 11 | 12 | 7 |
| 后 IMU | 63 | 181 | 111 |

这将问题定位到发布序号分配至接收之间，包含发送队列、Zenoh 传输和客户端处理；另一链路收到的样本证明至少部分缺失与接收路径有关。当前不能再细分到唯一组件，也不能把全部缺口归因于物理雷达漏采。并行探针会增加负载，以上数字仅代表该观察窗口。

脚本 [audit_gaps.py](../m1_preflight/airy_adapter/audit_gaps.py) 可重复执行。汇总见 [gap_audit.json](evidence/gap_audit.json)，原始测量保留在 Orin `artifacts/real_sensors/gap_audit.samples.json`。

## 2. 运行保护

线上统一使用 [AdapterEngine](../m1_preflight/airy_adapter/adapter_engine.py) 与 [InputGuard](../m1_preflight/airy_adapter/stream_guard.py)，线上和录包测试共用逻辑。所有四路先通过检查才开始输出；10 ms 最大空闲等待的循环独立检查断流，故障锁定全部适配输出。

| 条件 | 行为 |
| --- | --- |
| 启动 5 秒仍缺一路 | 锁定，等待期间不输出 |
| IMU 100 ms / 点云 350 ms 未收到消息 | 锁定 |
| 相邻已接收样本的设备时间间隔 >50 ms / >250 ms | 分别锁定 IMU / 点云所在整条适配链 |
| 时间重复、回退、超龄或过分超前 | 锁定 |
| 主机墙钟跳变、profile 过期或来自未来 | 锁定或拒绝启动 |
| 错坐标名、缺字段、非有限测量 | 锁定 |
| ROS 发布者改变或不唯一 | 锁定 |
| Zenoh 源 GID 改变、序号重复/倒退 | 原始接收器停止转发，保留状态；需要显式重启 |

Humble 的 Python 回调不提供逐消息 GID，因此 ROS 发布者核对使用发现图；源 Zenoh 身份在接收器内直接按每条 attachment 检查。运行保护属于输入软件，硬件急停由现场独立保障。Linux 调度及回调执行时间可能延迟检查，阈值不是硬实时保证。

恢复必须先保存日志、排查原因、结束旧建图/定位会话，再显式重启受影响的接收器/适配器、重新测量时钟及初始化定位。断流后恢复数据不会自动清除故障。新增预检入口会拒绝锁定或不新鲜的接收器。

## 3. 故障回放与节点测试

[20 项录包检查](evidence/fault_replay.json) 全部通过，包括正常 12264 条基线，以及 IMU/点云/全部断流、断流后重连、启动缺流、重复、乱序、设备时钟突跳、延迟、错误 frame、缺点云字段、逐点时间错位、IMU NaN、发布者重启、主机时钟跳变、过期配置、源 GID 变化、序号重复和未来配置。使用原始录包副本与虚拟时钟，未改原始 bag，也未向机器人注入故障。

[7 项实际 ROS 节点检查](evidence/fault_ros.json) 全部通过：domain 180 / localhost 合成输入下验证 IMU 断流、点云断流、全流断流、错 frame、ROS 发布者重启、过期和启动缺流。IMU 断流约 101.2 ms 触发，所有用例在队列排空后输出不再增加，恢复数据也没有续发。首次节点测试发现 Humble 回调签名不兼容，修复后重跑通过。

错误 frame 测试不能发现数值合法但物理安装方向错误的标定，这部分仍需真实标定和现场观测。

## 4. 真实输入复检与现场衔接

新版守护实际处理约 126 秒后，后点云间隔达到 0.300004 秒，触发 `source_gap`。截至锁定共输出前/后点云 1233/1258 帧、IMU 25273/25264 条；之后没有自动恢复。报告见 [guarded_preflight.json](evidence/guarded_preflight.json) 和 [锁定状态](evidence/guarded_adapter_status.json)。原始接收器保持运行、来源稳定，供继续排查。

该结果证明保护能够阻止异常后续接，不代表输入稳定性通过。下一次现场先检查板内发送/传输配置与同步状态，复跑输入预检；同时补实机外参。通过后再进行建图、定位，最后才是运动测试。

具体可复现命令与阈值见 [AIRY 操作说明](../m1_preflight/airy_adapter/README.md)。没有新增 SDK 会话、运动控制器、机器人速度输出或自动恢复服务。
