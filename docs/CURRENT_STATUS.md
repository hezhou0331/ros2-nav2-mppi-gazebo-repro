# M1 真机导航准备情况说明

更新：2026-09-13。当前目标是把 M1 的真实 AIRY 点云和 IMU 接入 RoamerX，完成建图、定位和导航前的准备。**当前尚未开始真实建图或自主行走导航。**

## 已完成

- 本机到外接 Orin 已公钥免密连接；部署使用 NVMe、ROS 2 Humble 和独立依赖，未改动其他机器人工作区。
- 真实链路已打通：狗内导航板 `.100:7447` 的 Zenoh 数据服务 → 外接 Orin → 前后点云/IMU → 私有适配话题。无需建立控制 SDK 会话。
- 20 个 RoamerX 导航包构建完成；AIRY 驱动准备及独立原生 XYZIRT 算法输入分支构建通过。导航仍以已锁定的 RoamerX 为基础。
- IMU 从 g 转为 m/s²，默认姿态明确标为不可用；AIRY 字段和逐点时间已适配，真实录包与原生解码验证通过。软件时间偏移保持同雷达点云/IMU 的相对时间。
- 断流、时间异常、坏帧和发布者变化会停止适配输出，恢复数据不自动续接；20 项录包故障回放及 7 项实际 ROS 隔离节点测试通过。
- 坐标链的几何计算与隔离 ROS 测试通过；合成地图上的实际规划服务绕障与不可达目标检查通过。这些不代表真实坐标标定或运动闭环通过。

## 最新真实检查

2026-09-13 静止复检的三分钟输入窗口通过：前后点云约 9.96 Hz、IMU 约 199.9 Hz，比较窗口内原始唯一帧均有对应适配输出，没有触发保护。完整预检仍因缺少真实外参退出 2，拒绝生成建图配置。

此前出现过约 300 ms 的后点云间隔并触发保护；本轮准备阶段也记录到约 300 ms 间隔，正式窗口最大约 200 ms。曾出现源发布者身份变化并触发接收锁定，保存记录、确认新来源稳定后，只显式重启了我们自己的接收器。**单次窗口通过不表示缺口根因或长期稳定性已经解决。**

## 尚未解决及计划

| 问题 | 当前证据与限制 | 解决计划 |
| --- | --- | --- |
| 数据间歇缺口 | 至少部分缺失发生在发布序号分配至接收之间，唯一瓶颈未定位 | 保留序号/设备时间/接收耗时诊断，结合板内发送和驱动配置继续定位，修复后做重复窗口验证 |
| 时间同步 | 软件偏移可用；两轮约七分钟内板间偏移变化 24–29 ms；硬件同步未验证 | 读取设备同步状态及真实驱动计时配置，验证相对时延与漂移；不把接收时间或固定偏移当作精确同步 |
| 真实安装外参 | 有标称位置，但完整旋转和本设备 IMU–LiDAR 标定未核实 | 优先读取本台 M1 的驱动/标定和 AIRY DIFOP；对照实物确认位置、朝向、机身参考点及驱动是否已变换点云 |
| 内部资料访问 | `.100` 的数据服务可读，现有公开参数/TF 未提供外参；尚未登录其文件系统 | 获取已有合法文件访问入口或由设备提供方导出配置，不能声称机器内没有数据 |
| 建图定位及运动闭环 | 尚未真实验收 | 标定/同步和输入条件满足后，再现场配合采集、建图定位、隔离规划控制，最后开展低速运动测试 |

前后各 20 帧静态点云已完成几何分析，IMU 显示接近静止特征；未知平面没有自动当作地面，未用猜测填入外参。静止数据无法独立确定全部安装变换和动态时延。
